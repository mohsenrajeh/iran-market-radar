# چرخه یادگیری و تنظیم کنترل‌شده

هدف این بخش کم‌کردن خطای قابل‌کنترل است، نه تضمین سود یا حذف ریسک بنیادی. نتیجه یک معامله به‌تنهایی دلیل تغییر استراتژی نیست.

## مسیر پنج‌مرحله‌ای

1. **ثبت:** هر خرید، افزایش، کاهش و فروش با سیگنال، snapshot، نسخه مدل، هزینه، MFE/MAE و R ثبت می‌شود.
2. **تحلیل:** پس از بسته‌شدن، post-mortem و درس ساختاریافته ایجاد می‌شود؛ این خروجی فقط فرضیه است.
3. **کاندید:** بعد از حداقل ۷۰ معامله قابل‌ردیابی در دو رژیم، ۵۰ نمونه قدیمی‌تر train و حداقل ۲۰ نمونه جدیدتر OOS می‌شوند.
4. **گیت OOS:** کاندید فقط وقتی پذیرفته می‌شود که Brier روی قطعه زمانی دیده‌نشده بهتر از امتیاز خام باشد. قاطی‌کردن تصادفی گذشته و آینده ممنوع است.
5. **فعال‌سازی:** مالک سامانه نسخه پذیرفته‌شده را صریحاً فعال می‌کند. نسخه قبلی آرشیو می‌شود و قابل ردیابی است.

## چیزهایی که خودکار نیست

- هیچ زیان منفردی حد ضرر، وزن استراتژی یا شرط بنیادی production را عوض نمی‌کند.
- پیشنهاد تحقیق بدون تغییر پارامتر واقعی و runner بک‌تست اجازه تغییر نمایشی وضعیت ندارد.
- کالیبراتور نتیجه معامله را پیش‌بینی قطعی نمی‌نامد؛ فقط احتمال خام را با شواهد خارج‌نمونه تنظیم می‌کند.
- Fundamental shock، توقف نماد، صف، خطای داده و تغییر مقررات حذف‌شدنی نیستند و با گیت داده/ریسک مدیریت می‌شوند.

## کنترل‌های رابط

- «ساخت نسخه آزمایشی» فقط در وضعیت `READY_FOR_CANDIDATE` فعال است.
- نسخه ردشده با دلیل و Brier قبل/بعد حفظ می‌شود.
- «فعال‌سازی نسخه بهتر» تنها برای artifact با وضعیت `CANDIDATE` فعال است.
- `automatic_promotion_enabled=false` قرارداد ثابت API و UI است.

## بازگشت و ممیزی

curve کالیبراسیون به‌صورت JSON، همراه fingerprint دیتاست، اندازه train/OOS، رژیم‌ها، Brier، ECE، زمان فعال‌سازی و شناسه مالک ثبت می‌شود؛ فایل pickle یا اجرای کد ناشناس وارد هسته نمی‌شود. rollback با فعال‌سازی یک کاندید معتبر دیگر انجام می‌شود و artifact قبلی حذف نمی‌شود.
